# agent-sdk 源码白话详解 · 总览与阅读指南

> 本文件夹是 `packages/agent-sdk/src` 目录下全部 7 个源文件的零基础白话详解。
> 每个源文件一份独立文档，直接存档、查阅、交接都可以用。

## 一、这套文档是干什么的、应该怎么读

**因为**这套代码工程是一个"大庄园管家 Agent"框架，里面的代码对零基础的人来说看起来像天书（一堆 `.ts` 文件、英文单词、看不懂的符号），**所以**需要这套文档：把每一个文件、每一个函数、每一个参数，用普通人能看懂的大白话讲清楚"为什么要有它、它干了什么、不写会怎样"。

**怎么读：**

1. 先把本文档（00 总览）读完，搞清楚整个工程是干嘛的、7 个文件分别管什么；
2. 再按 **01 → 07** 的顺序逐个读各文件的详解文档。这个顺序是按"后一个文件会用到前一个文件的东西"排的，顺着读不会卡壳；
3. 以后改代码前，先翻对应文件的详解文档里的"模块6：修改注意事项"，看清楚哪里不能动、动了会发生什么。

## 二、先搞懂整个工程是干嘛的（业务背景 → 程序目标 → 运行流程）

### 1、要解决什么业务问题

**因为**单靠一个大语言模型（AI 大脑）去回答所有问题，它一个人要懂做饭、懂清洁、懂采购、懂设备……知道得越多，脑子越乱、越容易瞎编，**所以**这个工程采用了"分而治之"的思路：

```
人类 👤（只跟管家说话）
   │
   ▼
大管家 Agent（packages/butler-core）—— 接活、分活、汇报
   │            │
   ▼            ▼
厨师 Agent     清洁工 Agent（packages/agents/*）—— 各管一摊
(chef)         (cleaner)
```

- **大管家**：唯一对外的"前台"。人类所有话都跟它说，它决定这活该派给谁，干完了由它转述结果。
- **子 Agent**（厨师、清洁工……）：各自只懂自己那一块领域，互相不认识、不直接来往。有跨界需求时，由管家转派。

**一句话总结：一个总协调管家 + 一群平级领域子 Agent，人类只见管家。**

### 2、agent-sdk 这个包在工程里管什么

**因为**每个子 Agent 都需要一套一模一样的"标准配置"——都要能接任务、都要按固定格式交作业、都要能连 AI 大脑、都要能存记忆，如果每个子 Agent 各写一套，代码会重复到没法维护，**所以**工程里专门建了 `packages/agent-sdk` 这个包：它是子 Agent 的"标准零件箱"，把上面这些公共能力做成现成的零件，任何新子 Agent 拿来就能用。

它对外提供 5 类零件（对应 5 个主要源文件）：

| 零件 | 文件 | 大白话作用 |
|---|---|---|
| 任务/结果信封协议 | `protocol.ts` | 规定管家给子 Agent 派活、子 Agent 交作业的"标准表格格式" |
| 领域能力适配器 | `capability.ts` | 把"真实本领"（查冰箱、下订单）包装成 AI 能调用的工具 |
| 记忆模块 | `memory.ts` | 给 Agent 配一个可以存取的"记事本" |
| 模型工厂 | `model.ts` | 负责"接通 AI 大脑"，支持 5 家厂商随插随用 |
| 子 Agent 基类 | `sub-agent.ts` | 把上面 4 样组装成一个完整能干活的子 Agent |

另外还有 2 个小文件：`index.ts`（统一出货窗口）和 `vendor.d.ts`（可选零件的类型说明书）。

### 3、整个程序一次对话的完整流程（先记住这个，读后面所有文档都不迷路）

1. 人类在界面/命令行说了一句话（比如"冰箱里还有几个鸡蛋？"）；
2. 程序入口先把模型厂商配置好（`await configureModel()`，详见 04 文档）；
3. 大管家模型读了这句话，决定派活给厨师，于是填一张"派活单"（TaskRequest：意图 + 参数，详见 01 文档）；
4. 系统自动把派活单补全成"正式任务信封"（TaskEnvelope：加上任务编号、目标领域）；
5. 厨师 Agent 收到信封，开一个**全新隔离的工作间**（独立 Agent 实例，详见 05 文档），能调用自己的工具（查库存等，详见 02 文档）、查写记忆（详见 03 文档）；
6. 厨师干完活，按固定格式交"结果信封"（ResultEnvelope：状态 + 一句话总结 + 细节 + 建议）；
7. 管家只看这张结果信封（看不到厨师的工作过程），转述给人类。

**这个流程贯穿全部 7 个文件，每份详解文档都会反复对照它来讲。**

## 四、开始读之前，必须懂的几个大白话概念

**因为**后面的文档会反复用到下面这些词，**所以**先在这里用大白话讲一遍，读的时候随时翻回来。

1. **Agent（智能体）**：一个"会自己思考、会调用工具、会按规矩交作业"的 AI 工作员。你可以理解成一个员工：大脑是 AI 模型，手是工具，规章制度是提示词（prompt）。
2. **模型（Model）**：AI 大脑本身，由不同公司提供（OpenAI、DeepSeek、Bedrock……）。就像员工可以换不同品牌的脑子。
3. **提示词（system prompt）**：给 AI 的"岗位说明书"，告诉它你是谁、你负责什么、干活要守什么规矩。
4. **工具（tool）**：AI 自己不会查冰箱、不会下单，得给它配"手"。每个工具就是一个函数：AI 决定"我要用查库存这个工具"，程序就真的去执行，把结果递回给 AI。
5. **信封（Envelope）**：管家和子 Agent 之间传话用的"标准表格"。派活用任务信封，交差用结果信封。表格字段固定、每格含义固定，谁都不能乱填。
6. **Zod 校验器**：一个 TypeScript 的"表格审查员"库。表格格式用代码写成规则，数据进来先过一遍审查，不合格直接打回。**因为**传话双方是 AI 模型，AI 说话不可靠、可能漏填乱填，**所以**必须有个铁面审查员把关。
7. **TypeScript（.ts 文件）**：JavaScript 的"加强版"，写代码时先声明每个数据是什么类型（文字还是数字），编译器能提前帮你抓错误。运行前要先"编译"成普通的 .js 文件（本工程编译输出到各包的 `dist` 目录）。
8. **SDK（Software Development Kit）**：软件开发工具包，就是"现成零件箱"。别的包不用自己造轮子，从这里拿。
9. **Agent-as-Tool（把智能体当工具用）**：本工程的核心手法——每个子 Agent 对管家来说就是"一个工具"。管家填一张派活单（工具入参），子 Agent 返回一张结果单（工具出参）。

## 六、全局修改红线与易错点汇总（改代码前必看）

> ⚠️ **高亮警告区**：以下内容是从 7 个文件里提炼出的"全局红线"，各文件文档的模块6还有各自的细项。

1. **协议字段名绝对不能改**（`protocol.ts` 里的 `task_id`、`intent`、`status` 等）：管家、子 Agent、数据库三方都按这些字段名读写数据，改一个名字 = 全链路数据对不上号，程序直接瘫痪。
2. **`ResultEnvelope` 的 5 种状态值不能增删改**（`done / failed / needs_human / deferred / unavailable`）：管家模型靠这几个词决定下一步动作，子 Agent 开发文档也按它们培训模型。想加状态是全局工程改动，不是改一处代码的事。
3. **`defineSubAgent` 里那 5 个校验（id 格式、description 等）不能删**：删了之后，写错 id 的子 Agent 要等到运行时才会炸，而且炸的位置在模型调用深处，非常难排查。
4. **每次任务新建 Agent 实例这个设计不能改成"共用一个实例"**：改了会导致不同任务之间的对话历史互相污染（A 任务的聊天记录泄漏给 B 任务），这是"上下文预算保护"的核心。
5. **`defineDomainTool` 的 try/catch 和统一返回格式不能删**：删了之后，工具一报错就会把异常直接抛给 AI 模型，模型会把"程序崩了"理解成"任务成功"，造成假汇报。
6. **`createModel` 的动态 import 不能改成顶部静态 import**：改了会让程序启动时强制加载全部 5 家厂商的 SDK，没安装的厂商直接让整个程序崩在启动阶段，违背"用哪家装哪家"的设计。
7. **`meimaoapi` 加载器里自定义 `User-Agent` 请求头那行不能删**：删了之后眉猫 API 会拦截 OpenAI 官方 SDK 的默认请求头，请求直接失败（源码注释里明确写了这个坑）。
8. **改任何文件后必须重新编译**（在对应包目录跑 `npm run build`）：`.ts` 源码不编译不生效，别的包引用的是 `dist` 里的编译产物。忘了编译会出现"代码明明改了、运行还是老行为"的灵异现象。

## 七、本套文档的通用读法（每个文件详解都长一个样）

每份文件详解文档都固定分 6 个模块：

- **模块1**：文件整体基础介绍（是什么、为什么要有它、管哪摊事、跟谁打交道）
- **模块2**：文件内每一个核心函数/核心定义的超详细说明（为什么封装、为什么这么写、一步步在干嘛、什么时候被调用、干完有什么用、谁在复用它、有什么坑）
- **模块3**：文件内每一个参数的超详细说明（叫什么、什么类型、为什么需要、数据从哪来、内部怎么用、合法值是什么、起什么作用）
- **模块4**：关键逻辑与特殊代码说明（每段 if、循环、异常捕获为什么存在，删了会怎样）
- **模块5**：文件整体运行总结（从加载到干完活的完整流程、不可替代性、运行前提）
- **模块6**：可复用模块 / 易错点 / 调试关键点 / 修改注意事项（高亮）

读到任何不懂的词，回本文档"第四节 概念扫盲"查。
